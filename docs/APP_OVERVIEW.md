# 猫の日記 — アプリ説明資料

最終更新: 2026-07-25

---

## 1. 一言でいうと

**猫ごとに、日記・健康・写真を一箇所にまとめて残せるモバイルアプリ。**

複数の猫を飼っていても混ざらず、通院やワクチンの予定も忘れない。
電波が無い場所でも書けて、繋がったときに自動で同期される。

---

## 2. 誰の、何を解決するか

| 困りごと | このアプリの答え |
|---|---|
| 写真アプリに猫の写真が埋もれ、いつ何があったか分からない | 日付・気分・カテゴリ付きのタイムラインで残す |
| 猫が複数いると記録がごちゃ混ぜになる | 猫ごとにプロフィールを持ち、ホームで切り替えて絞り込める |
| 体重の増減や通院歴を後から聞かれても答えられない | 健康記録に蓄積し、体重は推移グラフで表示 |
| ワクチンや通院の予定を忘れる | 予定を登録すると通知が届き、ホームに直近の予定を表示 |
| 動物病院や外出先は電波が悪い | オフラインでも書け、復帰時に自動同期 |

---

## 3. 主な機能

### 日記
- 作成・編集・削除（削除は取り消し可能）
- 写真の添付（アップロード前に自動リサイズ）
- 気分 5 種（ごきげん / ねむい / あそびたい / おなかすいた / リラックス）
- カテゴリタグ 6 種（ごはん / あそび / おひるね / 通院 / お手入れ / その他）
- お気に入り、キーワード検索、猫での絞り込み
- 書きかけで画面を離れようとすると確認が出る

### 猫の管理
- 名前・毛色 6 種・性別・誕生日・目標体重・プロフィール写真
- 誕生日から年齢を自動計算（N歳Mヶ月）
- 日記 / 健康 / アルバムの 3 タブでプロフィールを表示

### 健康記録
- 体重・通院・ワクチン・投薬の 4 種類
- 体重は推移グラフで可視化
- 通院・ワクチンの**予定**を登録すると、当日に通知
- 予定は完了チェック・削除が可能

### カレンダー
- 月間表示。日記のある日にはその日の気分が出る
- 同じ日に複数の日記があってもすべて開ける
- 空の日をタップするとその日付で新規作成

### 統計
- 連続記録日数、総日記数、写真付き件数、気分の分布
- 猫ごとの切り替え表示
- データのエクスポート / インポート

### その他
- ライト / ダーク / システム連動テーマ
- 毎日の日記リマインダー（時刻指定）
- Google ログイン

## 5. データモデル

`src/types/index.ts` が単一の情報源です。

| 型 | 主なフィールド |
|---|---|
| **Cat** | id, name, color, gender?, birthDate?, weightGoal?, photoUri?, createdAt |
| **DiaryEntry** | id, catId?, date, title, content, mood, photoUri?, category?, favorite?, createdAt, updatedAt |
| **HealthRecord** | id, catId, type(weight/vet/vaccine/medication), date, weightKg?, title?, note?, createdAt |
| **Appointment** | id, catId, type(vet/vaccine), date, title, note?, done |

日記の `catId` は任意です（猫を指定しない日記も書ける）。

## 7. オフラインファーストの仕組み

書き込みは**必ず先に端末へ保存**し、そのあとリモートへ送ります。

```
保存操作
  ├─ 1. AsyncStorage に即時反映     ← UI はここで完了。待たせない
  └─ 2. オンラインなら Firestore へ
         ├─ 成功 → 完了
         └─ 失敗/タイムアウト → 未同期キューに積む
                                  → オンライン復帰時に自動送信
```

- **タイムアウト必須**: Firestore の読み書きはサーバー応答があるまで解決しません。
  端末が繋がっていても経路が詰まれば永久に待つため、`syncService.withTimeout()`
  で必ず打ち切ります（8 秒、写真アップロードは 30 秒）。
- **同期は到達可能なときだけ**: `syncPending*Ops()` は先頭で `isOnline()` を確認します。
  これが無いと猫一覧の更新のたびに通信待ちで UI がブロックされます。
- オンライン復帰は `SyncStatusBanner` が検知し、オフライン / 同期中 / 同期完了を表示します。

### ローカルモード

Firebase の環境変数が未設定のときは `isFirebaseConfigured` が false になり、
`isOnline()` が常に false を返します。ログインは端末内ユーザーで代替され、
データは AsyncStorage にのみ保存されます。**認証情報なしで全機能を試せます。**

## 8. セキュリティ

- Firestore の全ドキュメントが `userId` フィールドを持ち、`firebase/firestore.rules`
  で「自分のデータしか読み書きできない」ことを強制
- Storage は `/{userId}/{entityType}/{fileName}` 構成。書き込みは本人のみ、
  5MB 未満、`image/*` に限定（`firebase/storage.rules`）
- 写真はアップロード前に長辺 1920px へリサイズし、品質 0.7 の JPEG に圧縮

## 9. 現在の状態

**動作確認済み**（ブラウザ実機操作 + 自動テスト）

- 猫の登録 → 日記投稿 → カレンダー表示 → 健康記録 → 統計 → 設定 まで通し確認
- `npx tsc --noEmit` クリーン / ユニットテスト 45 件すべて成功
- iOS・Android ともネイティブバンドルの書き出しに成功

**利用開始に必要な作業**

1. Firebase プロジェクトを作成し、`.env` に認証情報を設定（`.env.example` 参照）
2. `firebase/firestore.rules` と `firebase/storage.rules` を Firebase Console に適用
3. オリジナルアイコン・スプラッシュの差し替え（→ `docs/ASSET_REQUIREMENTS.md`）
4. ネイティブビルド（`eas build`、または Expo Go で動作確認）

**未対応**

- アイコン類が未作成（現状は絵文字とプレースホルダ）
- 猫の共有（家族間での同一猫の共同編集）
- 写真の複数枚添付（1 日記につき 1 枚）
